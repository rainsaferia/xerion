# PI-020 XER Parser Proof of Concept Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a robust, isolated Primavera P6 XER parser adapter (`app.adapters.p6_xer`) capable of parsing XER exports from multiple P6 releases, extracting project metadata, WBS, calendars, activities, and relationships into canonical intermediate representations, handling edge cases (encodings, CRLF/LF, missing tables, unexpected columns), and preserving unknown records for diagnostics.

### Task 3: Core Parser Implementation (`app.adapters.p6_xer.parser`)

**Files:**
- Create `backend/app/adapters/p6_xer/parser.py`
- Modify `backend/app/adapters/p6_xer/__init__.py`

**Steps:**
- [ ] Define `XERParserError(Exception)` with `code`, `message`, and `actionable`.
- [ ] Implement `XERParser`:
  - Multi-encoding decoding (UTF-8 with fallback to cp1252 / latin-1).
  - Header tokenizer verifying `ERMHDR` format, version, and export date.
  - Table tokenizer supporting `%T` (table name), `%F` (field names), `%R` (record data rows), and `%E` (end marker).
  - Record parser for `PROJECT`, `CALENDAR`, `PROJWBS`, `TASK`, `TASKPRED`.
  - Date and duration normalizers (converting P6 date strings `YYYY-MM-DD HH:MM` or ISO dates to `datetime.date` / `datetime.datetime`, and durations/floats to float hours).
  - Relationship type mapper (`PR_FS` -> `FS`, `PR_SS` -> `SS`, `PR_FF` -> `FF`, `PR_SF` -> `SF`).
  - Unknown table and column preservation in `unknown_tables` and `source_fields`.
  - Warnings generation for unknown relationship types or unparseable non-critical dates.
- [ ] Expose `parse_xer_bytes` and `XERParser` in `app/adapters/p6_xer/__init__.py`.
